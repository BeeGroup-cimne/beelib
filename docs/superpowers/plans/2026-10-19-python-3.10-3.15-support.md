# Python 3.10–3.15 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make beelib install, import and run on CPython 3.10, 3.11, 3.12, 3.13 and 3.14, and track 3.15 in CI until its upstream wheels exist.

**Architecture:** The library code itself needs no changes. The work is in packaging metadata (dependencies and classifiers), one smoke-test file, and a GitHub Actions matrix that proves every version on every push.

**Tech Stack:** setuptools (`pyproject.toml`), pytest, GitHub Actions (`actions/setup-python@v5`).

**Spec:** There's no design doc; the user skipped brainstorming. The scope is "support all major Python versions up to 3.15", and these decisions were made while planning:
- Supported versions are 3.10–3.15. 3.8 and 3.9 are end-of-life and stay out.
- 3.15 is tracked but non-blocking. On 2026-10-19, `uv` could only fetch `3.15.0b3`, and on it `thriftpy2` (via `happybase`), `cassandra-driver`, `confluent-kafka` and `pandas<3` (capped by `morph_kgc`) have no wheels and fail to build from source.

The resolved versions are the same on 3.12 and 3.14: cassandra-driver 3.30.1, confluent-kafka 2.16.0, morph-kgc 2.10.0, pandas 2.3.3, thriftpy2 0.7.1.

Packaging bugs found along the way (these break *every* version in a clean environment):
- `src/beelib/beeredis.py` imports `redis`, but `redis` isn't declared and nothing pulls it in transitively.
- `src/beelib/beerest.py` imports `requests`. Today it arrives only transitively; it should be declared because the code imports it directly.
- `kafka-python` is declared but nothing imports it, since the code uses `confluent_kafka`.

## Global Constraints

- `requires-python = ">=3.10"` (unchanged).
- Classifiers list exactly 3.10, 3.11, 3.12, 3.13, 3.14. Add 3.15 only in Task 3.
- No new runtime dependencies beyond declaring the already-imported `redis` and `requests`.
- No changes to library behaviour under `src/beelib/` other than what a failing test forces.
- Tests must not need a live Kafka, Cassandra, Neo4j, Redis, HBase, Druid or Influx.

## Review Focus

1. **Clean-env install of a submodule** (`import beelib.beeredis` right after `pip install beelib`) must succeed. Covered by `test_all_modules_import` in Task 1, which runs in a fresh CI venv.
2. **Cassandra on 3.12+**, where `asyncore` is gone: the driver must still find an event-loop reactor, otherwise `Cluster()` raises `DependencyException` at connect time. Covered by `test_cassandra_has_reactor`.
3. **Mixed-version Kafka fleet**: a message pickled by `BeeKafka.__pickle_encoder__` on the newest Python must decode on 3.10, so the pickle protocol must stay ≤ 5. Covered by `test_kafka_pickle_roundtrip_protocol`.
4. **Deprecations raised by beelib's own code** on new versions (for example `datetime.utcnow` on 3.12+) must fail CI. Only beelib's warnings count; third-party ones don't. Covered by `[tool.pytest.ini_options] filterwarnings` in `pyproject.toml`, which applies at collection time too. Today only import-time deprecations are exercised; call-time ones get caught as tests start calling the code.
5. **3.15 job failure** must not turn the build red, but must stay visible. Covered by `continue-on-error` on that matrix entry in Task 2.

### Task 1: Fix dependency metadata and add a smoke test

**Files:**
- Modify: `pyproject.toml` (`dependencies` and `classifiers`)
- Create: `tests/test_smoke.py`

**Interfaces:**
- Consumes: the existing modules in `src/beelib/`, plus `beelib.beekafka.BeeKafka.__pickle_encoder__` / `__pickle_decoder__` (static, `beekafka.py:41-46`)
- Produces: `tests/test_smoke.py`, run by `pytest` in Task 2

- [ ] **Step 1: Write the tests in `tests/test_smoke.py`**

```python
import importlib
import pickle
import pkgutil
import warnings

import beelib

MODULES = [m.name for m in pkgutil.iter_modules(beelib.__path__, "beelib.")]


def test_all_modules_import():
    assert "beelib.beeredis" in MODULES and "beelib.beerest" in MODULES
    with warnings.catch_warnings():
        warnings.filterwarnings("error", category=DeprecationWarning, module=r"beelib\b")
        for name in MODULES:
            importlib.import_module(name)


def test_cassandra_has_reactor():
    import cassandra.cluster
    assert cassandra.cluster.DefaultConnection is not None


def test_kafka_pickle_roundtrip_protocol():
    from base64 import b64decode
    from beelib.beekafka import BeeKafka
    value = {"a": [1, 2.5, "x"], "b": None}
    encoded = BeeKafka.__pickle_encoder__(value)
    raw = b64decode(encoded)
    assert raw[0] == 0x80 and raw[1] <= 5   # PROTO opcode, readable by 3.10
    assert BeeKafka.__pickle_decoder__(encoded) == value
```

### Task 2: Add a CI matrix and document supported versions

**Files:**
- Create: `.github/workflows/tests.yml`
- Modify: `README.md` (`# installation` section)

**Interfaces:**
- Consumes: `tests/test_smoke.py` from Task 1
- Produces: a GitHub Actions job named `test (<python-version>)` that Task 3 flips

- [ ] **Step 1: Write `.github/workflows/tests.yml`**

- Trigger on `push` and `pull_request`.
- One job, `test`, on `ubuntu-latest`.
- `strategy.fail-fast: false`.
- `matrix.python-version: ["3.10", "3.11", "3.12", "3.13", "3.14"]`, plus `include: [{python-version: "3.15", experimental: true}]`.
- `continue-on-error: ${{ matrix.experimental == true }}`.
- Steps:
  - `actions/checkout@v4`
  - `actions/setup-python@v5` with `python-version: ${{ matrix.python-version }}` and `allow-prereleases: true`
  - `pip install . pytest`
  - `pytest tests -v`

- [ ] **Step 2: Add the supported-versions note to `README.md`, right under `# installation`**

> Supported Python versions: 3.10–3.14. Python 3.15 is tested in CI but not yet supported, because `happybase` (thriftpy2), `cassandra-driver`, `confluent-kafka` and `pandas<3` (via `morph_kgc`) don't publish 3.15 wheels yet.

Run: `git push -u origin build/upgrade-python`, then `gh run watch`.
Expected: 3.10–3.14 are green. 3.15 is red at the `pip install` step but the run as a whole passes. If 3.15 is green, do Task 3 now.
